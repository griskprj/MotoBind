
# Создание планового ТО

**Контекст:** Garage
**Триггер:** «Добавить ТО» на карточке мотоцикла
**Результат:** Maintenance создан в статусе planned

## Шаги
1. User открывает форму.
2. Выбирает мотоцикл (если их несколько).
3. Заполняет: категория (масло, тормоза, ...), название, описание.
4. Указывает план: пробег и/или дата.
5. Backend создаёт Maintenance (status=planned).
6. Если planned_mileage близко к текущему — сразу создаётся Reminder.

## Что может пойти не так
- Ни пробег, ни дата не указаны → 422 «Укажите план».
- planned_mileage < текущего пробега → предупреждение «Уже просрочено», но создаём.
- Категория не из списка → 422.

## Эндпоинты
- `POST /api/v2/maintenances` → `{ maintenance }`

## Решения
- Обязательно: мотоцикл, категория, название, хотя бы одно из (planned_mileage, planned_date).
- Название — динамический список на бэке с возможностью установки своего названия, содержание зависит от выбранной пользователем категории.
- Категории — фиксированный список на бэке (масло, фильтры, тормоза, цепь, шины, электрика, двигатель, прочее).
- Reminder создаётся автоматически, если planned_mileage - mileage ≤ 500 км или planned_date - today ≤ 14 дней.
- Статус overdue не хранится — вычисляется на лету.
