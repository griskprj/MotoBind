
# Онбординг

**Контекст:** Garage (вход из Identity)
**Триггер:** первый вход после верификации email
**Результат:** добавлен мотоцикл, создан базовый набор ТО, показан гараж

## Шаги
1. User видит экран приветствия: 2–3 предложения, зачем MotoBind.
2. Кнопка «Добавить мотоцикл» → форма (название, год, объём, пробег).
3. Backend создаёт Motorcycle.
4. Backend предлагает базовый набор ТО (3–5 работ по пресетам).
5. User подтверждает или пропускает.
6. Backend создаёт Maintenance (planned) с интервалами.
7. Редирект на /garage, карточка мотоцикла с ближайшим ТО.

## Что может пойти не так
- User не знает год/объём → поля необязательные, кроме названия и пробега.
- User пропустил quick-start → пустой гараж с CTA «Добавить первое ТО».
- Пробег 0 → ок, пресеты строятся от 0.

## Эндпоинты
- `POST /api/v2/motorcycles` → `{ motorcycle }`
- `POST /api/v2/maintenances/quick-start` → `{ created: [...] }`
- `GET /api/v2/garage` → `{ motorcycles, stats }`

## Решения
- Онбординг показываем только если у User 0 мотоциклов.
- Quick-start предлагаем, но не навязываем. Пропуск — не блокирует.
- Метрика Activation = добавил мотоцикл + создал ≥1 ТО за 24ч.
