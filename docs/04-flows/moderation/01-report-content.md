
# Жалоба на контент

**Контекст:** Moderation
**Триггер:** «Пожаловаться» на посте, комментарии, мануале, профиле мастера
**Результат:** Report создан, ушёл модераторам

## Шаги
1. User нажимает «Пожаловаться».
2. Выбирает категорию: спам, оскорбление, реклама, опасный контент, другое.
3. Опционально — описание.
4. Backend проверяет: не своя жалоба, не дубликат pending.
5. Backend создаёт Report, сохраняет snapshot контента (на случай удаления).
6. Модераторы видят жалобу в очереди.

## Что может пойти не так
- Жалоба на свой контент → 422.
- Дубликат активной жалобы → 409 «Вы уже пожаловались».
- Целевой контент уже удалён → 404, но snapshot сохранён.

## Эндпоинты
- `POST /api/v2/reports` → `{ report }` — body: `{ target_type, target_id, category, description }`
- `GET /api/v2/report-categories` → `{ categories }`

## Решения
- target_type: post | comment | manual | master.
- Snapshot обязателен: сохраняем контент на момент жалобы. Иначе после удаления нечего смотреть.
- Один User — одна активная жалоба на один target.
- Report categories — фиксированный список на бэке.
