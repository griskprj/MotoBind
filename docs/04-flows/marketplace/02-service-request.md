
# Регистрация мастера

**Контекст:** Marketplace
**Триггер:** «Стать мастером» в профиле
**Результат:** Master-профиль создан (pending), User получил роль master

## Шаги
1. User нажимает «Стать мастером».
2. Заполняет: имя/название, описание, адрес, телефон, специализации (список), услуги.
3. Backend создаёт Master (status=pending_verification), добавляет роль `master` в User.roles.
4. Модератор проверяет профиль (см. Knowledge → модерация).
5. После approve — Master.is_verified=true, виден публично.
6. User получает Notification (type=system) «Профиль одобрен».

## Что может пойти не так
- У User уже есть Master-профиль → 409.
- Пустое имя/телефон → 422.
- Мастер не одобрен → не виден в каталоге, но может принимать заявки от знакомых (по прямой ссылке).

## Эндпоинты
- `POST /api/v2/masters` → `{ master }`
- `PUT /api/v2/masters/me` → `{ master }`
- `POST /api/v2/masters/me/services` → `{ service }`
- `DELETE /api/v2/masters/me/services/{id}` → `204`

## Решения
- Один User — один Master. Привязка через `user_id` (UK).
- Роль `master` присваивается автоматически при создании профиля.
- Профиль виден публично только после модерации (is_verified=true).
- Услуги — простой список: title, price, duration_min. Без категорий в v2.
- Телефон — обязателен, это главный контакт.
