
# Регистрация

**Контекст:** Identity
**Триггер:** гость нажал «Создать аккаунт»
**Результат:** User создан, письмо отправлено, редирект на «Проверьте почту»

## Шаги
1. Гость открывает /register.
2. Вводит email, username, пароль, согласие с условиями.
3. Backend валидирует, создаёт User (status=pending_verification).
4. Backend генерирует токен, отправляет письмо.
5. Frontend: экран «Проверьте почту».

## Что может пойти не так
- Email занят → 409, показать «Уже есть аккаунт? Войти».
- Username занят → 409.
- SMTP упал → User создан, письмо не ушло, показываем «Отправить повторно».
- Спам-боты → rate limit 3/10мин на IP.

## Эндпоинты
- `POST /api/v2/auth/register` → `{ user }`
- `POST /api/v2/auth/resend-verification` → `{ message }`

## Решения
- Email и username нормализуем: lowercase, trim.
- Пароль: min 8 символов, без сложных политик.
- Согласие с условиями — обязательный чекбокс, поле `agree_terms: true`.
