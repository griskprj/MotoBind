
# Refresh токена

**Контекст:** Identity
**Триггер:** 401 от API (access истёк)
**Результат:** новые cookies, очередь запросов выполнена

## Шаги
1. Клиент получает 401.
2. Interceptor ставит запросы в очередь, шлёт POST /auth/refresh.
3. Backend читает mb_refresh, находит Session, проверяет срок.
4. Backend выдаёт новый access + новый refresh (ротация).
5. Старая Session помечается used, создаётся новая.
6. Очередь запросов повторяется с новым access.

## Что может пойти не так
- Refresh отсутствует/истёк → 401, редирект на /login.
- Session отозвана → 401, редирект на /login.
- Параллельные 401 → single-flight lock на клиенте, один refresh, остальные ждут.
- Refresh reuse (украденный токен использован дважды) → отзываем все сессии User.

## Эндпоинты
- `POST /api/v2/auth/refresh` → `204` + Set-Cookie ×2

## Решения
- Ротация refresh — обязательна.
- Single-flight на клиенте обязателен, иначе гонки.
- При reuse — жёсткий logout всех сессий.
