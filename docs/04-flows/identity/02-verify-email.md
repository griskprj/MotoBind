
# Верификация email

**Контекст:** Identity
**Триггер:** переход по ссылке из письма
**Результат:** User активен, автологин, редирект на /onboarding

## Шаги
1. User кликает ссылку /verify-email?token=...
2. Frontend отправляет токен на бэк.
3. Backend валидирует, ставит is_verified=true, status=active.
4. Backend выдаёт cookies (access + refresh).
5. Frontend редиректит на /onboarding.

## Что может пойти не так
- Токен истёк (24ч) → экран «Ссылка устарела», кнопка «Отправить повторно».
- Токен уже использован → «Email уже подтверждён», автологин.
- User забанен → 403.

## Эндпоинты
- `POST /api/v2/auth/verify-email` → `{ user, redirect_to }` + Set-Cookie

## Решения
- Токен одноразовый, TTL 24ч.
- Автологин после верификации — да, токен из письма доказывает владение email.
- Если User открыл ссылку в другом браузере — всё равно верифицируем и логиним на этом устройстве.
