
# Сброс пароля

**Контекст:** Identity
**Триггер:** «Забыли пароль?» на экране входа
**Результат:** пароль изменён, все сессии отозваны, редирект на /login

## Шаги
**Запрос:**
1. User вводит email.
2. Backend всегда отвечает 200 «Если email существует, письмо отправлено».
3. Если User найден и active → создаём токен (TTL 1ч), шлём письмо.

**Сброс:**
4. User кликает ссылку, вводит новый пароль дважды.
5. Backend валидирует токен, обновляет пароль, отзывает все Session.
6. Редирект на /login с тостом «Пароль изменён».

## Что может пойти не так
- Токен истёк → «Ссылка устарела», кнопка «Запросить новую».
- Токен использован → «Недействительная ссылка».
- Пароль слабый → 422.
- 3 запроса за час на email → 429.

## Эндпоинты
- `POST /api/v2/auth/forgot-password` → `{ message }`
- `GET /api/v2/auth/check-reset-token?token=...` → `{ valid, email_masked }`
- `POST /api/v2/auth/reset-password` → `{ message }`

## Решения
- Ответ на forgot-password всегда 200, чтобы не раскрывать существование email.
- После сброса отзываем ВСЕ сессии — обязательно.
- Токен одноразовый, TTL 1 час.
- Инвалидируем все предыдущие токены при создании нового.
